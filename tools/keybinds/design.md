# Раскладка Clayblock 1.3.2

`registered-keys.tsv` фиксирует 168 строк назначений из `options.txt` предыдущего запуска опубликованной ревизии `1df15b178afdf78eba954870d6ffc785dc6e47b6`. Файл настроек совпадает с авторским шаблоном KubeJS по SHA-256 `de26e58f184050a2ec7f9077d97fcd86d6607f8a4134011ab9aff1139f30fefc`. Это исходный список для офлайн-проверки. Он может не охватывать назначения, которые мод регистрирует позднее, или содержать авторские строки, не зарегистрированные в конкретной игровой сессии.

34 назначения Minecraft сохраняются, включая WASD, Space, Shift, Ctrl, мышь, инвентарь, чат, хотбар и клавиши панели Creative. Для крюков используются Mouse 4, Mouse 5 и N, для Smart Crafting — K, для поиска точек Xaero — I. Действия обработки и сортировки, для которых раньше пересекались Tab, K, средняя кнопка мыши и цифровая панель, получили самостоятельные клавиши. Неназначенные в авторском списке действия остаются неназначенными.

Модель проверяет совпадение клавиши и модификатора по всем парам. Для модов с неподтверждённым контекстом она считает совпадение конфликтом. Сопоставлены классы Minecraft/NeoForge 21.1.219, `InternalKeyMappings`, `JeiForgeKeyConflictContexts` и обработчики ввода JEI 19.27.0.340 из закреплённых JAR. Действия JEI в открытом экране отделены от движения и кликов по миру. В JEI простые и модифицированные клики проверяются раздельно, а жесты с одной кнопкой сохранены для разных областей интерфейса: поле поиска и предмет под курсором, закладка рецепта и кнопка настроек. Клавиши в модификаторах учитываются как физические клавиши.

После обновления модов обновите снимок и таблицу `CHANGES`, затем запустите из корня Clayblock:

```powershell
python -B tools/keybinds/build_preset.py
python -B tools/keybinds/check_preset.py
```

Эти проверки не запускают игру и не проверяют применение кнопкой или фактическую обработку ввода модами.
